# warehouse-navigator-client — ПК-клиент (Qt6/C++)

Десктоп-приложение для подготовки склада к навигации: ведение **ячеек, товаров,
размещений, плана склада и QR-якорей**, запуск **встроенного LAN-сервера** для
телефона и **экспорт офлайн-снимка** (`*.whnav.json`).

Хранилище намеренно простое: состояние редактируется в таблицах и сохраняется в тот
же формат снимка, что читают мобильное приложение и Node-сервер. «Экспорт офлайн» =
сохранение снимка; «LAN-сервер» отдаёт телефону те же REST-эндпоинты прямо из текущего
состояния (никакой БД).

## Возможности
- Вкладки: **Ячейки** (код + X/Y на плане), **Товары** (sku/название/штрихкод),
  **Размещения** (товар↔ячейка↔кол-во), **План** (стеллажи/стены/зоны), **QR-якоря**.
- **LAN-сервер** (QTcpServer): кнопка «Запустить» → показывает адреса вида
  `http://192.168.x.x:8088`, которые вводятся в мобильном приложении.
- **Открыть / Сохранить снимок** (`*.whnav.json`) — обмен с телефоном офлайн и резерв.
- **QR-якорь**: строка `SSNAV1|warehouseId|xM|yM|headingDeg` рендерится в **картинку
  QR прямо в приложении** (кодировщик Nayuki `qrcodegen`, MIT, в `third_party/`) —
  диалог показывает QR и сохраняет PNG для печати/наклейки в точке (X,Y).

## Сборка (Qt6, CMake)

Требуется Qt6 (Widgets + Network) и CMake ≥ 3.21.

```bash
cmake -B build -DCMAKE_PREFIX_PATH=/path/to/Qt/6.x/<kit>
cmake --build build --config Release
# запуск: build/warehouse-navigator-client (на Windows — build/Release/...exe)
```

Пример (Windows, MSVC):
```powershell
cmake -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=C:/Qt/6.5.3/msvc2019_64
cmake --build build --config Release
```

## Формат данных
Совпадает с [`../core`](../core) (модель и снимок) и обслуживается так же, как
[`../server`](../server). Координаты: X вправо (восток), Y вверх (север), метры;
курс 0° = север, по часовой.
