# warehouse-navigator-mobile — приложение навигатора (APK)

Expo / React Native приложение: сканирует QR-якорь склада, ищет товар, показывает
2D-карту со стрелкой «вы здесь», целевой ячейкой и маршрутом. Между якорями позиция
считается по датчикам телефона (PDR). Вся математика — из
[`@smartstack/warehouse-navigator-core`](../core); этот пакет — только UI и датчики.

## Режимы данных
- **Живой (LAN):** на ПК запущен [сервер](../server), телефон в той же сети Wi-Fi.
  В приложении вводится адрес сервера (`http://192.168.x.x:8088`).
- **Офлайн:** в приложение вставляется снимок склада `*.whnav.json` (экспорт из
  ПК-клиента). Навигатор работает без сети.

## Возможности
- Скан QR-якоря (`SSNAV1|warehouseId|xM|yM|headingDeg`) — точная привязка позиции/курса.
- Поиск товара → ближайшая размеченная ячейка → маршрут (стрелка, поворот, расстояние).
- **Стрелка выправляется по 3D-плану склада** (`navigatorGuidance` в ядре): если
  прямая на ячейку упирается в стеллаж/стену — направление отклоняется в сторону
  свободного прохода (как на повороте коридора). Далёкие препятствия за горизонтом
  обзора не учитываются. На карте — зелёная стрелка «куда идти» + подпись «обхожу
  препятствие». Это геометрия по известному плану, а не сегментация кадра камеры
  (план знает стены точнее и стабильнее при складском освещении).
- PDR между якорями: шагомер + курс (компас с компенсацией наклона + комплементарный
  фильтр с гироскопом + отсев магнитных аномалий), длина шага по Вайнбергу,
  выталкивание из стеллажей по плану (map-matching).
- **Оптика выправляет дрейф датчиков (ARCore/ARKit через ViroReact)** — работает в
  ФОНЕ постоянно (это ФУЗИЯ, а не отдельный режим; кнопка «📷 Камера» лишь переключает
  ПОКАЗ карта↔камера, фузию она не включает/выключает). PDR остаётся основой (быстрый,
  работает в темноте и у глухой стены), а оптика (визуально-инерциальная одометрия —
  дрейф-корректирована визуальными признаками) непрерывно подтягивает накопленный дрейф
  счисления к себе, а при крупном (видимом оптикой) расхождении выправляет жёстко —
  автоматический аналог пересканирования QR. Поза камеры → поза склада чистой математикой
  ядра (`makeArReference`/`arPose`), слияние — `fuseOpticalIntoPdr`, затем выталкивание из
  стеллажей. При потере оптического трекинга навигация не замирает — ведёт PDR, оптика
  до-выправит, когда снова «увидит». Индикатор внизу: «оптика держит/подстраивает/
  выправила дрейф N м». Поверх камеры — шеврон «куда идти» (выправленный по плану).
- Подсказка «пересканируйте якорь» после накопления дрейфа.

> **AR требует dev build.** ViroReact — нативный модуль, в Expo Go не работает.
> Нужен `expo-dev-client` + config-plugin `@reactvision/react-viro` (уже прописан в
> `app.json`) и сборка `expo run:android` / EAS. 2D-режим (PDR) и выправление стрелки
> по плану работают и без AR — на любом устройстве. QR читает `expo-camera`.

## Сборка APK

Требуется Node 18+, Android Studio / SDK (для локальной сборки) либо аккаунт Expo
(для облачной EAS-сборки).

```bash
cd core && npm install && npm run build   # ядро как зависимость (file:../core)
cd ../mobile && npm install

# Dev на подключённом устройстве/эмуляторе (включает нативный ARCore через ViroReact):
npx expo run:android

# Релизный APK через EAS (облако):
npm i -g eas-cli && eas login
eas build -p android --profile preview     # вернёт ссылку на .apk

# Либо локально: npx expo prebuild && cd android && ./gradlew assembleRelease
#   APK: android/app/build/outputs/apk/release/app-release.apk
```

Проверка типов: `npm run typecheck`.
